# 연구 성과 요약 공개 절차

`/research/progress`는 자동 실행 상태와 검증한 포트폴리오 비교를 보여주는 화면입니다. 작업 상태는 실행기 기록에서 읽고, 성과는 공개 history 디렉터리의 `progress.json`에서 읽습니다. 새로운 연구 결과를 웹에 공개할 때는 이 절차를 함께 적용합니다. UI/API 계약은 [진행 화면 운영 문서](research-progress.md)를 참조합니다.

## 갱신이 필요한 때

- 새로운 비용 반영 포트폴리오 비교를 완료했거나 공개 성과를 정정할 때, 근거 보고서와 함께 성과 catalog를 갱신합니다.
- 문서 정리·기술적 오류 수정처럼 새로운 성과 비교가 없는 작업은 성과 수치를 만들지 않습니다. 실행기 작업 상태는 자동으로 화면에 반영됩니다.
- 새로운 자동 작업에는 가능하면 `task_labels`에 사용자가 이해할 수 있는 한국어 제목을 추가합니다. 제목의 키는 작업 ID입니다.

## 근거와 비교 조건

1. 원본 결과·입력·공개 보고서의 SHA256을 검증합니다. 수익률을 Markdown 문장이나 agent 설명에서 추출하지 말고 검증된 결과 JSON의 원래 금융 값으로 작성합니다.
2. 기준안과 후보는 동일 입력·종목·평가 기간·비용 배수·측정 정의로 묶습니다. 다른 기간이나 종목의 결과를 누적 개선 곡선처럼 연결하지 않습니다.
3. `cohort_id`는 같은 입력 자료와 종목 집합에만 재사용합니다. 연구 시점과 평가 기간을 구분하며, 각 study에 입력·결과·공개 보고서 SHA를 보존합니다.
4. 수익률, 현금 비중, 낙폭, 실제 레버리지 비중, 거래일, 거래금액 회전율, 거래·환전 비용을 함께 기록합니다. 현금 평균과 중앙값은 `cash_statistic`으로 구분합니다. 연환산 회전율은 매수·매도 금액 합계 / UTC일 마지막 NAV의 평균 × 365.25 / 평가 기간의 포함 달력 일수입니다.
5. 개선되지 않은 결과도 보존합니다. 단일 연구의 수익 개선을 전체 전략의 최고 수익 또는 실거래 승인으로 표시하지 않습니다. 과거 재사용·배당·세금·당시 공개값 검증 여부를 사실대로 기록합니다. 현재 schema가 표현하지 못하는 새로운 측정 정의는 별도 계약 변경·검증 후 추가합니다.

## 검증과 원자적 교체

- 기존 `~/.local/share/jusik/research-history/progress.json`의 바이트와 SHA를 보관합니다. 신규 study ID를 사용하고 과거 항목을 임의로 삭제하거나 덮어쓰지 않습니다. 정정은 새 ID·보고서로 남깁니다.
- 후보 JSON을 별도 audit에 작성하고 `jusik.research_progress.ResearchCatalog.model_validate_json(...)`으로 검증합니다. 근거 artifact가 실제 history 다운로드에서 같은 SHA로 제공되는지도 확인합니다.
- `featured_comparison_id`는 명시적으로 선정한 기준 비교입니다. 최신 연구 또는 최고 수익률이라는 뜻이 아니므로 변경 이유를 기록합니다. 최신 연구 목록과 분리해 표시합니다.
- 공개 직전 기존 catalog의 SHA가 그대로인지 확인합니다. 달라졌으면 새 내용을 다시 읽고 두 변경을 모두 보존합니다.
- 같은 공개 디렉터리에 임시 파일을 배타적으로 만들고 쓰기·flush·fsync 후 파일 단위 `os.replace`로 교체합니다. 디렉터리 전체를 교체하지 않습니다. 실패한 임시 파일의 경로와 원인을 남깁니다.
- 교체 후 schema와 보존 항목을 다시 검증하고 `/api/research/progress` 및 `/research/progress`에서 날짜·값·보고서 연결을 확인합니다. 공개 파일·근거·검증 결과·handoff를 audit에 보관합니다.

성과 catalog 갱신은 연구 산출물 공개입니다. 실행기 설정, PAPER 정책, 거래 신호, 실제 주문을 변경하지 않습니다.

# Research 화면 재설계 요구사항과 검토 초안

- 작성일: 2026-09-13
- 상태: 요구사항 수집 중. 사용자의 추가 불만이 남아 있으며 최종 구현 명세가 아니다.
- 이번 산출물: 불만, 확인한 구조, 개선 제안, 후속 설계·검증 기준을 정리한 문서.
- 적용 대상: `/research`와 성과 비교·가상 관찰·근거 기록·연구 도구의 연결 흐름.
- 이 문서만으로 UI 구현, 연구 정책 변경 또는 전략 채택이 승인된 것으로 해석하지 않는다.

## 1. 문제와 지향점

사용자는 자료를 읽는 기준, 각 페이지의 역할, 비교 대상 사이의 관계를 이해하기 어렵다. 정보를 더 추가하기보다 목표와 결과의 관계를 먼저 드러내야 한다.

중심 흐름은 **목표 → 해결할 문제 → 운용 방식의 변경 → 검증 결과 → 결정 → 다음 확인 사항**으로 제안한다. 이것은 설명의 순서이며, 모든 연구가 이 단계를 완료했다거나 각 결과의 인과가 입증되었다는 뜻은 아니다.

첫 화면에서 사용자가 다음 질문에 답할 수 있어야 한다.

1. 지금 설정된 목표와 운용 조건은 무엇인가?
2. 각 목표는 어디까지 확인되었고 무엇이 부족한가?
3. 어떤 문제를 해결하려고 기존 방식의 무엇을 바꿨는가?
4. 비교 결과는 목표 달성에 어떤 의미가 있는가?
5. 무엇을 채택·보류했고, 다음에는 무엇을 확인하는가?

## 2. 사용자 요구와 불만

아래는 대화에서 직접 확인한 요구다. 구체적인 배치와 명칭은 아직 합의하지 않았다.

| ID | 사용자 불만·요구 | 개선 시 충족할 내용 |
| --- | --- | --- |
| U1 | 자료를 어떻게 읽어야 할지 모르겠다 | 읽는 기준과 순서를 화면 구조로 전달한다 |
| U2 | 현재 설정된 모든 목표를 보고 싶다. 달성도도 중요하다 | 전체 목표·조건과 목표별 판단을 빠짐없이 보여준다 |
| U3 | ‘확인한 증거’의 뜻이 해석되지 않는다 | 무엇을 확인한 결과인지 제목과 요약에 명시한다 |
| U4 | ‘같은 조건’이 무엇과 같다는 것인지 모르겠다 | 비교한 두 방식과 고정 조건·변경 조건을 구분한다 |
| U5 | ‘기준 4주 / 후보 A 8주’가 두 로직 비교인지 불명확하다 | 두 방식의 역할과 실제 규칙 차이를 설명한다 |

| U7 | ‘다음 판단’이 새 후보 탐색인지 다른 로직인지 모르겠다 | 판단 대상과 실제 다음 행동을 명시한다 |
| U8 | forward와 ‘새 시세부터 쌓는 관찰’의 역할을 모르겠다 | 관찰 대상·목적·시작 시점·종료 또는 재평가 조건을 설명한다 |
| U9 | 페이지마다 용어가 다르다 | 같은 대상을 같은 이름으로 부른다 |
| U10 | ‘현재 자료가 말해주는 범위’가 모호하다 | 내용이 예상되는 구체적인 제목과 요약을 쓴다 |
| U11 | 다른 이름의 링크가 같은 페이지로 간다 | 중복 링크와 역할이 겹치는 섹션을 통합한다 |
| U12 | NEXT DECISION은 링크를 위한 섹션으로 보인다 | 독립적인 판단 내용이 없다면 제거·통합한다 |
| U13 | 단순함·확장성·인과·이해 용이성이 중요하다 | 연구가 늘어도 공통 구조를 유지하고 근거 없는 인과는 만들지 않는다 |

## 3. 코드와 설정에서 확인한 사실

확인 범위는 코드·설정 문서다. 실행 중 화면, 실시간 API 결과, 전체 연구 산출물은 이번 초안에서 검증하지 않았다.

- [개요 화면](../frontend/app/research/page.tsx): 목표·확인한 증거·다음 판단, 대표 비교, 결과의 한계, 하단 NEXT DECISION 영역이 있다.
- 같은 파일의 ‘같은 조건 비교 보기’, ‘전체 진행 현황’, ‘근거 읽기’는 모두 `/research/progress`로 연결된다.
- [진행 화면](../frontend/app/research/progress/page.tsx): 대표 비교, 연구별 결과, 자동 개발 상태와 작업 목록을 함께 보여준다. 연구별 카드에는 기간·종목·후보 수익률·비용·보고서가 있지만 연구 질문과 채택 이유를 설명하는 구조가 부족하다.
- [메뉴](../frontend/app/research/research-navigation.tsx): 연구 개요·성과 비교·가상 관찰·근거 기록·연구 도구로 구분한다. ‘성과 비교’의 목적지 제목은 ‘연구 진행 현황’이다.
- 개요의 forward 링크 문구는 비교 후보의 검증이 아닌 별도 고정 PAPER 10% 관찰이라고 설명한다. 실제 관찰 구성과 데이터는 구현 전 [forward 화면](../frontend/app/research/forward/page.tsx) 및 관련 API에서 추가 확인해야 한다.
- ‘기준 4주 / 현금 축소 후보 A 8주’는 사용자가 본 명칭이다. 정확한 규칙 차이와 해당 결과의 조건은 원본 산출물로 확인해야 한다. 주기만 달라졌다고 단정하지 않는다.

### 현재 목표·조건의 출처

[현재 연구 운용 조건](research-mandate.md)과 [JSON](research-mandate.json)을 확인했다. 아래는 작성 시점의 요약이며, 구현 시 최신 원본과 다시 대조한다. 이 문서는 새로운 운용 조건의 원본이 아니다.

| 구분 | 현재 설정 | 표시 제안 |
| --- | --- | --- |
| 위험 목표 | 초기 자본 포함 총 평가액의 운용 중 최고점 대비 최대 낙폭 20% | 실험별 측정 결과·계산 기준·조건 충족 여부 |
| 배분 범위 | 레버리지 상품 배분 20% 범위에서 연구 | 적용 규칙과 관측 결과를 구분 |
| 개선 선호 | 불필요한 현금 대기 축소, 투자 비중 확대 | 기준 방식 대비 현금 변화와 위험·비용 동시 표시 |
| 거래 선호 | 잦은 거래 지양, 거래 빈도·회전율·비용·비용 차감 수익 함께 평가 | 임의 임계값 없이 비교 결과 제시 |
| 자금 조건 | 초기 자본 1억원, 중간 인출 없음 | 운용 조건으로 표시 |
| 자료 조건 | 과거 lookback 3년, 짧은 이력이 주 연구를 막으면 해당 ETF 제외 가능 | 요구 기간과 실제 확보·검증 기간 구분 |
| 연구 범위 | 기존 종목 및 현금·광범위 지수·단기채 ETF 확장 | 실제 각 연구의 포함 종목과 구분 |
| 관측 조건 | 실시간 신호 탐지 | 주문 빈도와 동일한 뜻으로 표시하지 않음 |
| 미정 조건 | 투자기간 미정 | 미정 그대로 표시 |
| 운영 제한 | 실거래 유보, 기존 PAPER 10% 계약 보존 | 연구 목표 20%와 별도 정책임을 명시 |

## 4. 핵심 개선 제안

이하 내용은 사용자 요구를 충족하기 위한 제안이다. 배치·명칭·기능 추가는 검토 후 확정한다.

### 4.1 목표와 조건을 함께 찾되 성격을 구분한다

‘목표와 운용 조건’에서 전체 설정을 확인하게 한다. 수치 목표, 정성적 선호, 고정 조건, 미정 사항을 구분하며 자본금·실거래 유보 등을 달성률로 계산하지 않는다.

목표별 요약에는 목표의 의미, 기준, 현재 결과, 확인 범위, 부족한 점을 표시한다. 결과마다 대상 운용 방식과 검증 기간이 식별되어야 한다. 관련 결과가 여러 개면 하나만 골라 전체 달성으로 일반화하지 않는다.

권장 판단 표현은 ‘이 과거 실험에서 기준 충족’, ‘기준 미충족’, ‘검증 중’, ‘판단 자료 부족’이다. 실제 실행 기록 없이 ‘검증 중’을 붙이지 않는다. 정량 기준이 없는 선호는 ‘현금 비중 감소, 거래비용 증가’처럼 변화로 설명한다.

### 4.2 비교의 질문과 변경 내용을 수치보다 먼저 보여준다

연구 상세의 기본 순서:

1. 관련 목표와 해결하려는 문제
2. 기존 방식과 시험 방식의 쉬운 설명
3. 바꾼 조건과 동일하게 둔 조건
4. 결과와 목표별 이득·불리해진 점
5. 결정 및 근거, 아직 결정하지 못했다면 그 이유
6. 다음 확인 사항과 원본 보고서

변경 전후 규칙은 재조정 주기뿐 아니라 현금·배분·진입·위험 규칙까지 원본에서 확인한 차이를 표시한다. 여러 규칙이 함께 바뀌면 ‘이 변경 묶음에서 관측한 차이’라고 설명하고 특정 규칙의 효과라고 단정하지 않는다.

### 4.3 연구 목록을 질문과 결론 중심으로 바꾼다

목록 한 항목의 최소 내용은 ‘무엇을 알아보았는가 / 무엇을 알아냈는가 / 관련 목표 / 결정 상태’다. 상세 수치와 파일은 상세 화면으로 보낸다.

연구가 늘면 목표별 묶음과 진행·결정 상태를 먼저 활용한다. 검색·복잡한 필터·별도 대시보드는 실제 규모와 필요를 확인한 뒤 도입한다. 결과가 없거나 부정적인 연구도 근거가 있다면 보여주며 좋은 수익률만 대표로 고르지 않는다.

### 4.4 관찰 화면은 대상과 역할을 먼저 설명한다

첫 부분에서 ‘관찰 중인 방식 / 확인하려는 질문 / 시작 시점 / 현재까지 확보한 기록 / 다음 평가 조건’을 제시한다.

비교 후보와 관찰 대상의 정책·버전이 다르면 그 관계를 명시한다. PAPER의 10%와 현재 연구 목표의 20%는 별도 조건이다. 정확한 정책 의미를 확인하기 전 숫자만으로 쉬운 이름을 만들지 않는다.

관찰 기록이 있다고 후보 채택이나 실거래 준비가 완료된 것으로 표현하지 않는다. 데이터 대기와 수집 실패, 미시작 상태도 구분한다.

### 4.5 화면과 링크의 역할을 줄이고 명확하게 한다

| 현재 영역 | 제안 | 이유 |
| --- | --- | --- |
| 목표 카드 | 전체 목표·조건과 현재 판단으로 확장 | 자료를 읽을 기준 제공 |
| 확인한 증거 | 관련 목표의 연구 결과 요약에 통합 | 추상적인 독립 영역 제거 |
| 현재 자료가 말해주는 범위 | 결과 요약과 그 결과의 한계로 재배치 | 수치와 해석을 같은 위치에 제공 |
| 다음 판단·NEXT DECISION | 실제 결정·다음 확인 내용에 통합 | 내용 없는 링크 반복 제거 |
| 연구별 결과 | 질문·결론 중심 목록으로 수정 | 연구를 읽는 목적 제공 |
| 실행기·작업 대기열 | 운영 상세로 배치 검토 | 개발 작업 완료와 목표 달성의 혼동 방지 |
| 보고서·다운로드 | 관련 결과의 상세 근거로 유지 | 검증 가능성 보존 |

같은 목적지에는 같은 이름을 사용하고 본문 내 반복 진입점을 최소화한다. 전역 메뉴와 관련 결과의 상세 링크처럼 역할이 다른 반복은 허용할 수 있다. 링크 개수보다 이동 목적이 명확한지를 기준으로 판단한다.

## 5. 흐름 관점에서 추가 발굴한 개선점

### 5.1 현재 설정과 과거 연구 조건의 차이

과거 결과 옆에서 ‘이 연구가 따른 목표·정책 버전’을 확인할 수 있게 한다. 현재 조건과 다르면 차이를 설명한다. 최신 목표를 과거 결과에 덮어씌우거나, 이전 정책의 충족 결과를 현재 목표 달성으로 사용하지 않는다.

### 5.2 비교 대상의 일관된 식별

동일한 운용 방식은 개요·연구 상세·관찰에서 같은 이름과 버전을 사용한다. ‘후보 A’ 같은 내부 식별자만 노출하지 않는다. 표시 이름과 내부 ID를 구분하고, 관련 연구가 있다는 이유만으로 같은 방식으로 취급하지 않는다.

### 5.3 목표 사이의 상충 관계

현금을 줄였지만 낙폭이나 비용이 늘어날 수 있다. 목표별 결과를 같은 비교 안에서 보여주고, 사용자에게 확정받지 않은 가중치로 종합점수·종합 달성률을 만들지 않는다. 우선순위가 없으면 결정에 필요한 미정 사항으로 남긴다.

### 5.4 결론과 결정의 분리

‘수익률이 증가했다’는 결과이고 ‘이 방식을 채택했다’는 결정이다. 결론, 결정 상태, 결정 이유와 근거 기록을 구분한다. 채택 기록이 없으면 ‘결정 기록 없음’으로 표시하며 완료된 실험을 자동 채택으로 바꾸지 않는다.

### 5.5 자료의 신선도와 부족한 이유

페이지 확인 시각과 실제 데이터 기준 시각을 구분한다. 자료 없음·불러오기 실패·검증 실패·관찰 기간 부족을 같은 빈칸으로 합치지 않는다. 각 상태는 의미와 가능한 다음 확인 방법을 짧게 제공한다.

### 5.6 요약에서 상세로 이동해도 맥락 유지

목표에서 연구를 열면 상세에도 관련 목표와 선택한 비교 대상을 유지한다. 돌아갈 위치를 제공하고, 단순히 모든 링크를 같은 상세 페이지 상단으로 보내지 않는다. 필요하면 기존 경로의 앵커 또는 선택 상태를 활용하되 경로 변경부터 결정하지 않는다.

### 5.7 ‘다음’에는 구체적 조건을 담는다

‘추가 검증 필요’ 대신 확인할 질문, 필요한 자료, 완료 또는 재평가 조건을 제시한다. 일정이 없으면 날짜를 추정하지 않는다. 사용자의 판단이 필요한지, 시스템 작업인지, 데이터 대기인지 구분한다. 실제 다음 작업이 없다면 만들어내지 않는다.

### 5.8 주의 문구를 해당 판단 근처로 이동

배당·세금 제외, 자료 재사용, 검증 기간 등의 한계는 해당 결과에 붙인다. 모든 영역에 같은 경고 문단을 반복하지 않되, 상세에만 숨겨 요약을 오해하게 만들지도 않는다. 핵심 제한은 요약에 짧게 유지한다.

## 6. 첫 화면 구성 예시

아래는 배치 검토용이다. 실제 값·현재 성과·결정을 나타내지 않는다.

```text
연구 현황
현재 확인된 상태 한 문장 / 결과 데이터 기준 시각

목표와 운용 조건
  목표 | 기준 | 현재 결과와 확인 범위 | 판단
  [전체 운용 조건]

목표를 위해 확인한 연구
  연구 질문
  기존 방식 → 시험 방식: 바꾼 규칙
  결과 요약: 좋아진 점 / 불리해진 점 / 아직 모르는 점
  결정과 이유 또는 결정 기록 없음
  [연구 상세]

현재 진행하거나 기다리는 확인 사항
  대상 방식 / 목적 / 실행 또는 대기 상태 / 재평가 조건
  [관련 관찰 또는 연구 상세]

보조 탐색: 연구 목록 / 운영 도구 / 근거 기록
```

‘다음 확인 사항’에 실제 정보가 없으면 그 상태를 짧게 설명한다. 화면을 채우기 위한 카드나 링크 전용 섹션은 추가하지 않는다. 모든 목표의 가시성을 유지하면서 좁은 화면에서도 같은 읽기 순서를 보존한다.

## 7. 용어 후보

정확한 명칭은 사용자 검토 후 확정한다. 경로 이름은 UI 문구와 분리한다.

| 기존 표현 | 대체 방향 |
| --- | --- |
| 확인한 증거 | 관련 연구의 질문·결과를 직접 제목으로 사용 |
| 같은 조건 비교 | 기존 방식과 시험 방식 비교, 고정 조건은 바로 설명 |
| 기준선 / 후보 A | 기존 방식 / 시험 방식 + 실제 특징을 담은 고유 이름 |
| 재조정 | 처음 나올 때 ‘보유 종목의 투자 비중을 다시 맞추기’ 설명 병기 |
| 다음 판단 | 실제 결정 또는 다음 확인할 질문 |
| 새 시세부터 쌓는 관찰 | 관찰 시작 이후 시세로 가상 운용한 기록 |
| 연구별 결과를 따로 보기 | 연구 질문과 결과 목록 |
| 유니버스 | 비교 대상 종목 |

## 8. 데이터 확인과 구현 범위

### 기존 자료에서 먼저 확인할 것

- 최신 mandate의 전체 항목과 적용 시점.
- progress API의 비교 식별자, 양쪽 방식, 기간·종목·비용·측정 기준 및 대표 비교 선정 방식.
- 연구 보고서와 사전등록에 있는 질문, 규칙 차이, 결론, 조건 버전.
- forward의 실제 정책과 비교 후보의 관계, 데이터 기준 시각, 관찰 시작·상태·평가 조건.
- history의 기록이 연구 결과·운영 작업·정책 결정 중 무엇을 뜻하는지.

### 현재 제공 여부를 추가 조사할 정보

목표와 연구의 연결, 안정적인 방식·버전 식별, 규칙 차이 요약, 구조화된 결론·결정 이유, 목표별 판단 범위, 다음 평가 조건은 API와 원본 자료를 대조해야 한다. 화면에 없다는 이유만으로 데이터 자체도 없다고 단정하지 않는다.

필요한 경우 기존 catalog나 메타데이터 확장을 우선 검토한다. 공통 데이터 형태는 ‘목표 / 방식 / 연구 / 비교 / 관찰 / 결정’의 관계를 설명하는 수준으로 잡고, 처음부터 별도 DB·범용 워크플로 엔진을 만들지 않는다.

이번 초안의 범위 밖은 전략 변경, 새로운 실험 실행, PAPER 정책 수정, 목표 임계값 신설, 자동 채택, 실거래 연결이다. UI 개선에 실제 성과 정정이 포함되면 [성과 공개 절차](research-progress-publication.md)를 별도로 적용한다.

## 9. 후속 작업 순서와 완료 기준

1. 남은 사용자 불만을 수집하고 이 문서의 요구와 제안을 갱신한다.
2. 현재 화면·API·원본 자료를 대조하여 누락 정보와 실제 관계를 확인한다.
3. 페이지 역할, 용어, 요약·상세 경계를 텍스트 시안으로 검토한다.
4. 확정된 범위만 구현 계획으로 전환한다. 개발 시작 시 저장소 운영 절차를 따른다.
5. 실제 자료와 자료 부족 상태로 이해 가능성 및 연결 정확성을 확인한다.

### 검토용 수용 기준

- [ ] 사용자가 전체 목표·선호·운용 조건과 미정 사항을 찾을 수 있다.
- [ ] 목표별 결과의 대상·기간·검증 범위를 알 수 있고 임의 달성률이 없다.
- [ ] 두 방식의 차이와 동일하게 둔 조건을 보고서 다운로드 없이 설명할 수 있다.
- [ ] 각 연구가 왜 필요한지, 무엇을 알아냈는지, 어떤 결정이 있었는지 알 수 있다.
- [ ] 과거 비교와 현재 관찰이 같은 방식인지 다른 방식인지 구분된다.
- [ ] PAPER 10%와 현재 연구 목표 20%가 혼동되지 않는다.
- [ ] 같은 대상과 목적지에 일관된 이름을 사용한다.
- [ ] 중복 섹션을 없애도 결과의 중요한 한계와 원본 근거에 접근할 수 있다.
- [ ] 자동 개발 작업 완료를 목표 달성이나 전략 채택으로 표현하지 않는다.
- [ ] 자료 없음·실패·기간 부족·미정 상태를 정상 성과나 실행 중으로 오인하지 않는다.
- [ ] 새 연구 하나를 추가해도 새로운 최상위 메뉴 없이 기존 구조로 설명할 수 있다.
- [ ] 데스크톱과 좁은 화면에서 목표부터 상세 근거까지 읽는 순서가 유지된다.

### 아직 결정하지 않은 사항

- 최종 메뉴명과 페이지 통합 범위, 기존 URL 유지 방식.
- 첫 화면의 결과 선정 기준과 연구가 많을 때의 기본 정렬.
- 정성적 목표의 판단 기준과 목표 간 우선순위.
- 부족한 연구 메타데이터의 작성·검토 주체와 갱신 방식.
- 결정·채택 기록의 실제 출처와 없는 경우의 처리.

후속 Codex는 이 초안을 구현 완료 명세로 취급하지 않는다. 확인된 사실·사용자 요구·제안을 구분하여 유지하고, 추가 대화에서 확정한 범위만 구현한다.
